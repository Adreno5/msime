# Agent Note: 活动词典保留已预热的 n 元表

Status: implemented

## Problem

全拼和双拼构造时加载 n 元表，却丢弃返回的 `Arc`。整句查询重建路径、检查文件名别名并锁住八槽共享缓存；其它词典淘汰条目后，活动词典在按键路径重新探测缺失文件或映射和检查完整表。精确分配测试先预热也不能隔离随后发生的淘汰。

## Decision

构造时保留二元/三元表的 `Option<Arc<NgramTable>>`，整句查询只克隆这两个句柄。缺失表在活动词典生命周期内保持缺失；资源分代后由新词典捕获新表。共享缓存仍负责新词典的加载复用和容量限制，双拼数据库未打开时仍不加载表。全拼的整句候选、整句重新转换与双拼整句候选共用 `SentenceNgramTables::options` 的默认评分配置，不重复维护参数。

内部路径型配置函数仅保留作完整冻结测试对照。`lattice` 模块不对 crate 外公开，没有对外接口变更。n 元表的文件打开、格式验证、排序检查、映射和桶索引代码不变。

## Existing decisions

已检索活跃树的 `ngram`、共享表缓存及配置入口。[解析缓存投影](2026-10-14-quanpin-resolution-cache-projection.md)和[系列前缀借用](2026-10-14-quanpin-series-prefix-borrow.md)通过关闭词网格隔离预算，部分重叠但保留其查询优化与验证边界；[模糊路径延后拥有](2026-10-14-fuzzy-path-deferred-strings.md)记录尚未确认的干扰，本篇补受控证据。九键数字网格提案的查询规划无关；双拼纠错整句保留评分配置单一来源，没有完全吸收或过时提案。

## Alternatives considered

- 增大全局缓存：改动小、减少淘汰；不采用，因为容量有限时仍会在活动词典按键路径重新读表，无界缓存又无法及时释放闲置资源。
- 只预构造路径：省去路径拼接和别名检查；不采用，因为每次仍加锁、哈希并可能重新映射，构造时已有需要保留的句柄。
- 只关闭相关测试的词网格：能稳定预算并保留独立行为测试；不采用，因为生产查询仍受共享淘汰影响。

## Verification

新增全拼/双拼真实整句合并回归在旧生产实现上真实失败：缺失表时共享淘汰前全拼53、双拼77次申请，淘汰后分别55、79，多出的两次是两张表路径重新加入共享缓存。固定的预热不能阻止这个受控复现。旧全量偶发失败的具体线程时序未记录，本篇证明该机制足以产生相同的两次额外申请，不倒推宣称已捕获那次失败现场。

改后四种有/无二元三元表组合分别在全拼与双拼上比较热查询、强制16条其它路径淘汰后、unlink表文件再淘汰后。完整 `WordItem` 字段含分数派生权重及顺序一致，候选向量容量和精确申请数保持。unlink不改变已映射inode的字节，旧评分持续可用。无表热整句全拼53→45、双拼77→69；共享淘汰后由55→45、79→69。这里计数包含Rust堆申请，不含SQLite C堆。

固定 `87593cb4791e16297798f3542f817aa80da8be48` 的完整旧配置正文，仅移除注释并保留作测试。四种组合的旧热配置申请分别8/6/6/4次，持有表的配置克隆均零申请；比较评分参数、表存在状态和实际二/三元分。活动句柄的克隆用指针同一性对照；旧共享入口只对照表内容，不假设两次调用之间共享缓存一直驻留。`Weak` 来源是活动句柄，强制共享淘汰后验证拥有者仍保留映射，丢弃拥有者后验证释放。独立新资源目录捕获新表，先捕获缺失再出现文件也不改变旧快照。

## Consequences

活动词典持有映射至销毁，不再因共享缓存淘汰释放它；存储仍是可回收的只读文件映射，索引堆占用每表约256 KiB。同代词典通常共享 `Arc`；共享条目已淘汰后创建的新词典仍可能独立加载，这是容量受限缓存原来的行为。共享缓存自身仍限八槽，不主张全部进程表的内存上界只有八张。

资源更新须通过分代和重新构造词典，不得原地改写映射文件；缺失表同样固定于活动词典快照。活动句柄不读取用户输入、不能产生拥有循环。不引入新依赖、unsafe或全局容量调整，也不承诺CPU、RSS或宿主延迟测量结果。

遵循标准库 [Arc共享拥有与克隆](https://doc.rust-lang.org/std/sync/struct.Arc.html)和当前依赖 [LruCache容量及淘汰规则](https://docs.rs/lru/0.18.5/lru/struct.LruCache.html)；构造时保留已有句柄避免跨缓存驻留假设。
