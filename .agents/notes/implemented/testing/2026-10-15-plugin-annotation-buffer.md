# Agent Note: 插件候选注释直接写入截断缓冲

Status: implemented

## Problem

桌面插件指令候选的行旁注释在每次视图读取时先把标题和注释拼成完整 `String`，再按 32 个 UTF-16 码元收集另一份截断字符串。注释有固定长度上限，超长插件注释会产生一份永远不会返回的中间文本。

## Decision

保留标题、控制字符过滤、空值处理和 UTF-16 字符边界语义；直接把标题、分隔空格和注释按剩余码元写入最终 `String`，不创建完整拼接文本。只在存在可显示内容时申请结果，按原总字节长度（含分隔符）与 96 字节上界的较小值预留一次容量。32 个 UTF-16 码元的 UTF-8 表示最多 96 字节，因此写入不会扩容；长度计算使用饱和相加。`Option<String>` 的公开所有权边界不变。

## Alternatives considered

- **继续完整拼接再截断**：实现直观，但固定上限之外的文本仍申请并复制一次。
- **为注释结果增加 runtime 常驻字符串缓冲**：可以复用容量，但 `script_annotation` 返回拥有型字符串，多个候选同时存在，复用会改变所有权边界并需要额外复制。
- **返回借用注释视图**：可以完全避免结果分配，但公开 `Candidate` 需要拥有型注释，且插件行与普通候选共享 `Option<String>` 契约。

## Verification

真实 runtime 使用合成 `/uuid` 插件行和 40 个“注”。新增回归测试在旧实现上测得 7 次分配并失败，直接构造后测得 1 次并通过。冻结旧拼接和收集实现，与新构造器对照 8 种标题和 8 种注释的 64 种组合，覆盖空内容、ASCII、中文、emoji、混合字符和 32 码元边界；完整返回值相等，非空结果只分配一次，请求字节不超过 96，并且少于旧实现。原有真实入口测试继续覆盖控制字符过滤。

既有连续插件查询测试实测从每次 49 次分配降至 46 次，同步更新预算。测试分配计数模块及 `count_bytes` 仅在 `cfg(test)` 中增加 crate 内可见性，供私有构造器的冻结对照使用。

`cargo test -p msime-input-runtime` 的 284 项测试通过；fmt、Clippy、笔记检查及 `git diff --check` 通过。`bash scripts/verify-local.sh --quick` 通过：覆盖 Rust workspace、Android/wasm 目标、Android 宿主检查、Linux 公共组件和原生宿主（87 项测试）、macOS 原生宿主及 Apple bridge 构建、本机可运行的 Windows 原生测试（149 项）。Windows 完整交叉构建和 HarmonyOS 真打包因缺少环境跳过；本次未做设备安装验收。只读审查通过。

## Consequences

每次读取插件注释只拥有最终结果，超长注释不再完整拼接、分配后丢弃，也不保留常驻缓存。短文本按原长度申请，长文本容量最多 96 字节；UTF-16 计数和完整字符写入避免拆开代理对，标题截断后不再写入分隔空格。控制字符过滤仍在原入口执行。

收益是分配次数和分配请求字节下降；未测量 CPU 延迟、堆峰值或端到端速度，不作相关提升声明。结果仍为拥有型字符串，因此非空注释每次读取保留一次必要分配。
