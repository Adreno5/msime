# Agent Note: 拼音大小写还原直接比较编码字节

Status: implemented

## Problem

全拼、双拼和会话共用 `apply_segmentation_cases`。为判断切分编码能否沿用原始输入的大小写，它先建立两份去分隔符字符串，再为原始输入创建 ASCII 小写副本。比较后这些字符串全部丢弃，返回文本却还要独立分配；匹配与不匹配的常见 ASCII 输入均承担三份临时字符串。

## Decision

用两条字节迭代器跳过 ASCII 撇号，仅对原始输入流做 ASCII 小写折叠，再逐字节比较。保留空输入、比较失败时的原切分返回，以及成功后原有大小写回填循环和拥有型结果。切分编码本身不额外转小写，维持原先单侧折叠的准入条件。

## 历史决策审计

- [辅助码检测借用输入](2026-10-09-shuangpin-helpcode-detection-cow.md) 无直接重叠：管理模式检测中的输入存储，本篇只管理大小写回填前的相等性比较。
- [双拼模糊候选重标](2026-10-15-shuangpin-fuzzy-relabel-borrow.md) 无直接重叠：管理候选编码的写回容量，不涉及大小写回填。
- 其余检索命中的日文/越南语大小写转换、日文查询流式输出、前缀请求所有权及辅助码模式/缓冲笔记均与本函数契约无关。

## Alternatives considered

- 借用无分隔符原文，仅在有分隔符或大写时建立副本，便于复用既有字符串 API；切分编码通常含分隔符，有效原文也常含大写，仍保留中间存储。
- 对两边做不区分 ASCII 大小写比较，表达简洁；原逻辑只折叠原始输入一侧，切分编码自身含大写时可能改变是否进入回填，不能放宽这一条件。

## Verification

旧实现的常见 ASCII 输入回归以 4 次分配失败，优化后匹配、不匹配和微软分号输入均只分配拥有型结果的 1 次，纯分隔符仍为 1 次，任一输入为空时均为 0 次。用 7 种字符组成长度 0 到 3 的 400 个输入，加 8 个多音节边界和 2 个长输入，共 410×410＝168100 组，与冻结的旧实现逐结果对照；覆盖单侧大小写折叠、前导/连续/末尾分隔符、不匹配、Unicode 字节和 128 音节长输入。

现有会话回归的分配预算同步收紧，功能断言保持：

| 操作 | 旧预算 | 新预算 |
| --- | ---: | ---: |
| 光标前缀展开 | 319 | 316 |
| 忽略方案按键 | 28 | 25 |
| 末尾输入 | 130 | 127 |
| 末尾退格 | 19 | 16 |
| 设置光标 | 25 | 22 |
| 移动光标 | 25 | 22 |
| 光标处输入 | 202 | 196 |

引擎单元测试 2101 项通过、19 项忽略，golden 31 项通过；Clippy、Rustfmt、差异检查、笔记检查与本地 quick 门禁通过。quick 包含 Linux 原生宿主 87 项测试、macOS 原生宿主及 Apple bridge 构建，不代表设备验收。

## Consequences

比较阶段不创建规范化存储，遇到不匹配可提前结束；输出仍按原接口返回拥有型 `String`。只折叠原始输入一侧的 ASCII 大小写，只跳过 ASCII 撇号，保留回填循环的已有字节语义；全拼与双拼使用同一实现。本片不引入跨帧缓存或新接口，不承诺整个快照零分配或端到端延迟收益。
