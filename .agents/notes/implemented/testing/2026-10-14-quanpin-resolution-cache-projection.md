# Agent Note: 全拼查询槽按需投影解析缓存

Status: implemented

## Problem

`insert_online_words` 只读取 `SeriesResolution::cache_key`，`expand_initial_candidates` 只读取规范切分来构造不带纠错前缀的键。热缓存却先克隆整个解析结果，包括完整纠错音节及两档替代切分，随后把这些副本全部丢弃。

## Decision

私有解析方法接收即时投影回调。热命中把缓存结果包装为借用的 `Cow<SeriesResolution>`；冷未命中仍按原逻辑计算、克隆缓存副本，并把原拥有值交给回调。常规候选查询用 `Cow::into_owned` 保持原拥有结果；在线回写只取得缓存键，冷值直接转移该字符串，热值只克隆这一字段；首字母展开从规范切分构造原来的无纠错前缀键。

借用只持续回调，不跨过后续词典可变调用。缓存结构、完整键碰撞核对、FIFO 年龄、失效范围及冷缓存容量保持原样。

常规 `query_exact` 仍取得独立拥有的解析结果；系列缓存未命中后的主切分直接借用该局部结果的 `segmentation`，交给主读法查询和替代切分合并。后续词典可变调用不修改这个局部解析，故无需另复制主切分。供候选标记使用的 `self.pinyin_segmentation` 副本继续独立拥有，借用不逃逸本次查询。此处仅收窄冗余副本，不将常规查询改为借用解析缓存。

## Existing decisions

检索活跃笔记中的 `resolution_cache`、`SeriesResolution`、解析缓存、纠错缓存和切分借用键，没有同一解析结果投影决定。插件行迭代、词库缓冲、macOS 预览 token、系统主题、语音服务与 AI endpoint 的解析结果记录均无关。[热行缓存投影](../../implemented/testing/2026-10-14-quanpin-row-cache-projection.md)只处理词库行的临时页，部分重叠于首字母展开调用，保留其字段和行缓存决定，不吸收或归档。

## Alternatives considered

- 用 `Arc<SeriesResolution>` 替换缓存拥有值：热命中可以共享全部字段；不选，因为会增加冷路径分配和引用计数，还需重新判断直接保存计算结果的多余容量。现有两个回写调用只需要键，借用投影足够。
- 回写调用各自增加缓存快查：改动局部；不选，因为会复制完整键核对和冷解析逻辑，或让冷未命中重复哈希和查找。
- 回调只接收 `&SeriesResolution`：接口简单；不选，因为常规候选查询仍要独立拥有结果，冷路径将多克隆一份；区分拥有和借用可以转移原结果及在线键。
- 把主切分字符串移出局部解析：也能省去复制；不选，因为其余查询仍引用完整解析及纠错字段，局部只读借用就能覆盖主读法和替代合并，无需引入部分移动。

## Consequences

热回写省去不需要的完整纠错结果副本，常规候选查询和冷缓存克隆仍然存在。即时回调不增加缓存状态、引用计数、公开接口或依赖。

在线回写须保留 `C:` 纠错前缀，首字母展开继续按旧契约去掉它；不能把两个查询槽规则合成一个。常规查询必须继续取得拥有结果，缓存借用不得逃逸回调；冷缓存仍使用原克隆副本，不能用投影顺手转移过量预留容量。
