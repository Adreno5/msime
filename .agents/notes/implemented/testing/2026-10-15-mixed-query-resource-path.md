# Agent Note: 混排表情词库路径按需构造

Status: implemented

## Problem

`CandidateQueries::mixed` 在查完英文后无条件解析 `msime-others.db` 路径。只有英文、日文或符号参与混排，或者输入不足两个字节而不查 emoji、颜文字时，路径及现名/旧名兼容查找都没有消费者，仍在逐键刷新中申请临时路径存储。

## Decision

仅在输入达到原有门槛且启用 emoji 或颜文字时调用 `RuntimePaths::resource`，同一次混排的两类查询共享解析结果。仍在每次有效查询中解析现名/旧名，不增加跨按键缓存。候选查询、来源、顺序和外层容量保持原样。

## Related notes audit

- [混排表情查询借用前缀](../../implemented/testing/2026-10-08-mixed-query-prefix-borrow.md)：部分重叠，约束同一查询的前缀所有权；本篇仅负责词库路径的构造时机。
- [混排表情查询复用结果行缓冲](../../implemented/testing/2026-10-08-mixed-result-buffer.md)：部分重叠，结果行缓冲的容量约定继续成立。
- 符号候选、英文领先与九宫格表情的笔记描述候选行为，不改变本次路径选择。

## Alternatives considered

- **缓存已解析的路径**：每次有效查询也可以省掉路径申请与兼容查找，但现名/旧名选择由实际文件状态决定，永久缓存会冻结选择，不采用。
- **在 emoji 和颜文字分支各构造一次路径**：条件最直观，但两项同时开启时重复构造同一路径，保留一次共享解析。
- **继续无条件解析**：结构最简单，但未查询该词库的按键仍承担路径申请与兼容查找。

## Verification

新增完整混排入口的分配回归在旧实现上实际失败，纯英文分支产生 4 次路径申请；优化后三组纯英文、单字母表情与日文分支均为 0 次，候选字段、插入位置和外层容量同时断言。38 项混排测试通过，完整引擎测试通过（2063 项单元、31 项 golden，16 项本地计时默认忽略），Clippy 通过；提交前还运行格式、笔记校验和 quick 门禁。

## Consequences

未使用表情词库的混排不再构造路径，也不做无消费者的现名/旧名探测。有效 emoji、颜文字查询仍共用一次原路径解析，不缓存文件选择或数据库内容。代价是多一个共享条件分支；分配计数只衡量 Rust 路径存储，不能推导端到端时延收益。
