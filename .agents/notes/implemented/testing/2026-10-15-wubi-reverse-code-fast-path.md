# Agent Note: 五笔反查显示候选的身份校验快速路径

Status: implemented

## Problem

五笔方案的宿主快照需要给显示候选追加反查编码。引擎已经在原始候选刷新时按候选保存编码，但显示列表还会经过混输、固定位置、个人重排、前缀筛选和本地行插入。直接把显示下标当成原始候选下标会把别的候选编码附到当前行；旧的按词查找语义正确，却会为每个显示行线性扫描原始候选。

## Decision

在保留旧的按词查找作为完整回退的前提下，增加带身份校验的快速路径：只有显示行与引擎原始行在同一位置且词面相同，并且对应编码非空时，才直接读取该位置的已缓存编码；任何长度、顺序或词面不一致都回退到旧入口。重复词继续沿用旧入口的首个同词编码语义。快速路径只减少安全可证明的同序扫描，不把显示索引当成原始索引。

## Alternatives considered

- **直接按显示下标读取原始编码**：实现最小，但显示候选经过重排、混输插入和过滤后不再与原始顺序同构，会产生错误注释。
- **每次快照建立词面哈希表**：能把任意显示顺序变成近似常数查找，但会为每次快照新增哈希表分配，且需要明确重复词的首项语义；在常见同序路径上不如有界快速路径直接。
- **让所有显示候选携带原始身份**：语义最完整，但要把身份扩展到本地候选、插件行和多组平行数组，跨越引擎与宿主快照契约，改动面超出本切片。

## Verification

- 同序原始候选直接复用已有编码，不执行线性按词扫描。
- 混输、固定位置、个人重排、前缀候选、单字过滤和重复词均与旧按词入口产生完全相同的注释。
- 越界、长度不一致或词面不一致时不误用别的行编码。
- 针对五笔反查的宿主测试通过；完整引擎测试、golden、Clippy、格式、笔记门禁和 quick 在提交前运行。

## Consequences

快速路径只在词面和边界都匹配时生效；错位、越界和重复词仍走旧按词入口，因此显示候选的重排和插入不会改变编码语义。代价是同序路径仍要做一次词面比较，错位路径保留线性查找。
