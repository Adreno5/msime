# Agent Note: 独立句子重排静态评分栈缓冲

Status: implemented

## Problem

`ordering::rerank_pick` 的静态证据分支只比较最多九条回答按键的候选，却先为候选下标、静态逐字分和文本子集分别建立三个临时 `Vec`。这些容器只在调用句子模型前搬运借用数据，模型返回和最终候选都不取得它们的所有权。

## Decision

静态证据分支使用三个长度为 `STATIC_RERANK_LIMIT` 的调用方栈数组，按原顺序写入最多九条有效候选；证据缺失、字数为零或有效候选不足两条时继续回退原有模型路径。模型收到的文本切片、静态均值、前九条预算和首选下标保持不变。候选超过九条时只扫描到预算上限，不为未参与比较的行创建临时存储。

## Existing decisions

[候选重排文本引用栈缓冲](2026-10-09-rerank-text-buffer.md)已经为一般模型路径的短文本引用保留栈数组；本篇只覆盖静态证据混合分支的三个输入数组。 [独立句子排序静态证据](../bug-fix/2026-10-14-rerank-static-evidence.md)继续约束证据单位、来源过滤和缺失回退。

## Alternatives considered

- 继续为三个输入建立 `Vec`：实现最直观，但每个热调用都为固定九条上限支付临时堆分配。
- 始终使用九条栈数组并截断所有模型输入：可以统一代码，却会改变超过短列表边界的既有 `best_where` 输入契约；本篇只改变静态证据分支。
- 在 `Reranker` 对象上保存可复用向量：可跨调用复用，但引入跨会话可变状态和失效管理；固定九条上限的调用方栈数组更简单。

## Verification

先加入栈输入的零分配回归测试；冻结旧实现时因缺少 `STATIC_RERANK_LIMIT` 和 `fill_static_rerank_inputs` 入口而编译失败，证明测试未提前通过。实现后测试确认两条合成完整读法写入下标、自然对数均值和文本切片且分配数为零。完整引擎测试、golden、Clippy、Rustfmt、差异、笔记和 quick 门禁在提交前重跑。

## Consequences

短静态证据重排少三份临时输入容器的堆申请，增加约九条下标、分数和文本引用的栈空间；模型本身返回的评分向量仍由 `Reranker` 接口拥有。本篇不声称改变模型推理、候选质量、端到端时延或大列表路径的复杂度。
