# Agent Note: 繁简转换前缀查找不申请端点向量

Status: implemented

## Problem

`Table::longest_prefix` 每次调用都按最大词条长度申请临时端点 `Vec`，规范化对每个剩余字符调用，简转繁还逐位置查词组和单字。上一片真实 C ABI 分配测量发现 14 字节合成 ASCII 的繁转简有 16 次申请，其中 14 次是查找端点向量；这是可消除的热路径开销。

## Decision

正序遍历最多 `longest` 个字符得到前缀字节边界，再逆序遍历该借用切片的字符端点，按长到短查询现有 HashMap。保留任意词条长度、ASCII 开头的键、UTF-8 字符边界、先词组再单字、兼容字规范化和 IDS 规则，不增加依赖或改变表内容。

## Existing decisions

检索 `longest_prefix`、字形转换、繁简转换和 OpenCC。完全同机制的活跃笔记不存在。[离线释义 JSON 分配](../../implemented/testing/2026-10-14-offline-gloss-empty-json.md)部分重叠：本次处理该篇刻意排除的转换成本，原 JSON 预算和行为不变。[候选渲染边界](../../implemented/architecture/2026-10-13-cross-platform-candidate-rendering-boundaries.md)保留各宿主调用共享转换的归属。脚本插件的 OpenCC 数据、空格、语音、标点和拆字决定仅消费转换或描述独立数据路径，与此查找算法无关，不吸收或归档。

## Alternatives considered

- 固定栈数组保存端点：一次字符解码即可反向读端点，词条短时成本低；不选，因为把数据最长词条变成额外常量约束，或需要溢出回退，并未简化边界。
- ASCII 直接跳过查表：合成未命中请求会很快；不选，因为 vendored 区域词组表包含 `PN结`、`SQL注入攻击` 等 ASCII 开头键，会改变最大匹配结果。
- 改成 trie：共享所有候选长度的路径，不必逐前缀散列；暂不选，需要改变表结构、初始化和内存布局，当前证据首先支持去掉可独立验证的临时申请。

## Verification

固定基线 `d701b7890b177869bcab54141068b393f2ca6259` 的真实 Cargo 集成测试在输出相等之后按预期失败，当前实现通过。预热字典及逆表、测量窗口外准备合成输入和检查输出，线程局部计数只包住真实转换调用；空串为 0 次，其余所选 ASCII、中文、兼容字、emoji/辅助平面/假名混排和 IDS 的两方向均为 2 次。该预算依赖所选输出不扩容，不把任意文字的输出扩容算作算法回归，也不把首次初始化算成稳态。

既有离线释义 C ABI 预算保持独立计数转换成本并通过：4,096 行合成未命中请求从上一片的 69,667 次、1,296,680 请求字节降至 12,323 次、837,928 字节，回复保持空释义数组。本次减少 57,344 次和 458,752 累计请求字节，不是 RSS 或设备峰值内存。

新增单测以遍历表键选择最长前缀为独立参照，覆盖空串/空表、所有测试文字的字符前缀、ASCII 开头混排、二至四字节 UTF-8 和 88 字符词条。Rust 官方 [CharIndices 文档](https://doc.rust-lang.org/std/str/struct.CharIndices.html)确认可逆迭代；固定 OpenCC `26753884f1984add422f3b0249ccee8613deaff6` 的 [s2t 配置](https://github.com/BYVoid/OpenCC/blob/26753884f1984add422f3b0249ccee8613deaff6/data/config/s2t.json)仍为规范化加词组/单字组，未改动数据或来源。

CPU 证据用 `rustc -O` 在同一临时程序机械包含固定旧版与当前转换模块，复用相同 vendored 数据；两模块各持独立预热的 OnceLock/随机散列种子。逐个词典有效行的键、首值和键加合成混排后缀，对两方向共 328,848 次比较全部相等。空串、长短 ASCII、长短词组/繁体、兼容字、IDS 和长短混排共 11 组×两方向，九轮交替先后顺序；每轮迭代 `clamp(65_536 / max(字符数, 1), 64, 4096)` 次，输入构造、初始化和对照不计时，转换和输出回收计时。各轮平均单次耗时中位数：3,584 字符 ASCII 的 s2t 为 1,044,757→884,891 ns，配对旧/新中位比 1.179；t2s-char 为 145,552→98,842 ns，比 1.480。非空 20 组配对比为 1.077–1.480，空串基本持平。独立散列种子、主机负载和重新解码都会影响耗时，这只是共享转换函数的配对测量，不含 FFI 包装/词库查询或宿主输入链路，不设机器间计时门禁。

`cargo test -p msime-client-core -p msime-host-api --locked` 全部通过：client-core 1,422 项单元测试和 6 项集成测试，Host API 623 项单元测试和 14 项集成测试，两包合计 4 项原有忽略用例，文档测试通过。两包 `cargo clippy --locked --all-targets -- -D warnings` 通过，格式、差异检查和笔记校验通过。独立审查未发现问题，并复跑转换分配预算与 UTF-8 最长前缀参照测试。

本地 `bash scripts/verify-local.sh --quick` 通过，覆盖契约检查、Rust workspace、Android target 与宿主 JVM 冒烟、Wasm、原生 macOS 宿主及共享 Apple 桥接编译。Linux 因无 Docker、Windows 因无 MinGW、HarmonyOS 因缺工具链/资源跳过；缺少 app bundle 的桌面目标按门禁规则跳过。没有执行设备验收。

## Consequences

消除稳态前缀查找堆申请；该片测量包含两个转换输出缓冲及其必要扩容、首次字典和逆表初始化。后续无变化阶段借用原文见[转换扫描借用](2026-10-14-chinese-conversion-borrow-unchanged.md)，本篇端点查找决定不变。逆向检查字符端点会再次解码字符，该片最大匹配的散列查询次数不变，后续[首字节过滤](2026-10-14-chinese-prefix-byte-filter.md)排除必然失败的查询；将来若证据指向重复散列成本，可以独立评估 trie。测试复用 Host API 集成测试分配器，各测试二进制独立，全局计数器不进入生产代码。未改文件读写、目录、权限或 Android 资源，不把本地编译与单测描述成设备验收。
