# Agent Note: Runtime 共用候选排列应用

Status: implemented

## Problem

内置在线候选、整句读法降位和桌面脚本插件都需要把同一个排列同步应用到候选文本、编码、注释、来源、固定座位、纠正标记、答案键以及 `engine_order`。这些字段漏同步会让显示行与提交行脱节。原先公共方法对八个数组分别调用 `apply_order`，同一排列重复遍历八次，超过 128 行还重复申请八份访问标记缓冲。

## Decision

`crates/input-runtime/src/runtime.rs` 的 `Runtime::apply_candidate_order` 用 `ordering::apply_order_with` 一次遍历排列，在交换回调里同步移动七个候选字段数组及引擎座位映射。循环算法和栈/堆访问缓冲仍由 Engine 的通用排序模块持有，回调只描述调用方的交换操作，不让 Engine 认识 Runtime 字段。单数组的 `apply_order` 也委托给同一原语，继续保留原接口与不可克隆元素的所有权语义。

插件变换继续在调用后同步自己的 `plugins.occurrences`，因为重复项身份是插件侧的附加数组；排列规则和锁定逻辑仍保留在各自调用方。恒等排列不调用回调；不新增排列验证，调用方仍保证下标是合法排列、数组长度一致。Runtime 保留逐数组的调试长度断言。

检索活跃笔记 `apply_order`、`visited` 与访问缓冲，既有[线性循环算法](../../implemented/testing/2026-10-12-order-permutation-linear-cycles.md)持有算法和访问缓冲的取舍，本篇持有 Runtime 并行字段的同步边界；两篇均原地更新，不新增重复笔记。

## Alternatives considered

- 把插件身份数组也放进 Runtime 公共方法：一次调用可同步所有相关数组，避免漏同步；但该数组只在桌面插件模块存在，且不属于引擎候选快照，跨平台接口会被插件实现细节污染。
- 修改 Engine 的 `apply_order` 让它认识 Runtime 的所有数组：可以在一个函数里写完所有交换，但 Engine 不拥有宿主的快照和插件身份，违反分层边界；通用交换回调只接受两个下标，不承载宿主状态。
- 保留八次调用并复用一份访问缓冲：改动直接，能够避免七次重复分配；每个数组仍要清空标记、重新检查恒等性并遍历相同循环，交换回调能同时消除这些重复工作。

## Consequences

候选排列的同步字段只有一个 Runtime 维护点，三条排序路径仍保留各自规则。大列表的 Runtime 循环访问缓冲由八份降为一份，短列表继续使用 128 字节栈标记；引擎座位映射首次建立的分配仍存在，排序索引和插件附加数组不在本次优化范围内。原地交换保留候选缓冲和字符串所有权，不增加常驻 Runtime 缓冲；公共 Rust 原语增加一个交换回调入口，调用方必须持续维护并行数组同步。

## Verification

新增真实 `Runtime::apply_candidate_order` 分配回归，32、127、128、129、1,024、4,096 行分别覆盖长循环与逆序。旧实现的大列表预算真实失败；4,096 行首次建立引擎映射并重排时为 9 次、65,536 申请字节，新实现为 2 次、36,864 字节；单独的访问标记由 32,768 降为 4,096 字节。32 至 128 行保持一次映射分配，访问标记不分配。以上是 64 位宿主累计申请请求，不代表 RSS 或完整按键延迟。

语义回归覆盖 0、1、127、128、129、4,096 行，两次排列的引擎座位组合、全部七个候选字段、候选缓冲指针、已有映射时恒等排列零分配，以及显示行提交到对应引擎行。引擎既有测试通过单数组接口覆盖长度 0 至 7 的全部排列和栈/堆边界，确保抽取后的通用循环算法不漂移。

优化构建的独立微基准从固定基线 `84e009742a1067bc3580a0eba16f4695134b1cb7` 机械提取旧 `apply_order` 和 Runtime 方法，从本次源码提取新原语和方法，以三份字符串数组、四份标记数组和座位映射复现交换字段。对 8、32、128、129、1,024、4,096 行的长循环、逆序和恒等排列各做九轮交替配对，映射和候选在计时前构造，每轮处理约 262,144 总行次，至少迭代 64 次并逐字段比较旧新结果。4,096 行长循环各轮平均单次耗时的中位数为 69,828→23,397 ns，配对旧/新时间比中位数 3.013；逆序为 29,071→14,314 ns。18 组配对旧/新耗时比的中位数都大于 1，较小列表的纳秒结果容易受宿主噪声影响。这是提取函数和合成字段的本机微基准，不能推断完整输入链路或设备延迟。

`cargo test -p msime-engine -p msime-input-runtime --locked`：引擎 1,979 项、golden 31 项、Runtime 260 项及文档测试通过，15 项既有引擎用例默认忽略。两 crate 全目标 Clippy、Rustfmt、笔记校验和差异空白检查通过。


`CARGO_BUILD_JOBS=6 bash scripts/verify-local.sh --quick` 通过，包括 Rust 工作区、Android target、Wasm、Android Java 冒烟、macOS 原生宿主和共享 Apple 桥接编译。Linux 缺 Docker、Windows 缺 MinGW、HarmonyOS 缺工具链和预置资源的阶段跳过；本次未做设备输入法验收。
