# Agent Note: 繁简转换未变化的扫描借用原文

Status: implemented

## Problem

前缀查找已不申请临时端点，但 `convert_pass` 在没有变化时仍构造完整输出。简转繁先复制规范化原文，再构造最终输出；繁转简也为没有兼容字的输入构造规范化缓冲。上一片预热后的短长 ASCII 和普通中文两方向均申请两次，这个中间副本可以避免。

## Decision

共用转换扫描返回 `Cow<str>`：第一次实际变化时才申请并复制已扫描前缀；此前未命中或原文等值映射只推进位置。所有查表、最长匹配和 IDS 规则仍按原顺序执行。公开函数继续返回拥有型 `String`，简转繁最后一轮未变化时接管已有规范化缓冲或复制最初输入；繁转简逐字符逆表规则保持独立，不能改用带整段 IDS 跳过规则的扫描器。

## Existing decisions

按 `convert_pass`、`chinese_conversion`、字形/繁简转换和 `Cow` 检索。没有同一缓冲决定的活跃笔记。[前缀端点](../../implemented/simplification/2026-10-14-chinese-prefix-noalloc.md)部分重叠，继续持有查找算法和端点预算，本篇收窄其两个输出缓冲的常态成本，两篇互链。[离线释义 JSON](../../implemented/testing/2026-10-14-offline-gloss-empty-json.md)仍独立排除转换成本，不改其预算。[日文读音扫描](../../implemented/testing/2026-10-09-japanese-reading-stream.md)与[provider 转换缓冲](../../implemented/testing/2026-10-09-japanese-provider-conversion-buffer.md)仅提供已有借用/输出复用的参考，各自状态机、会话归属无关且保留。插件注释归属与共享渲染边界不变，不吸收或归档。

## Alternatives considered

- 先扫一遍确认会变化，再完整转换：保留现有拥有型扫描最简单；不选，因为变化文本重复查询同一张表，已经有证据表明查询成本不能忽略。
- 只对 ASCII 提前返回：长 ASCII 可省掉全部查询；不选，因为会形成额外的字典内容假设，且普通中文的无变化规范化同样有重复复制。以后若做字符过滤，必须由实际词典派生并单独测量。
- 把繁转简也写成通用最大匹配扫描：可以复用全部输出物化路径；不选，因为原逆表循环转换 IDS 内的繁体部件，而通用扫描保留整段 IDS，二者并不等价。

## Verification

固定基线 `b38d4e19d1b3ddf9688076836df073b057f0a4ca` 的真实 Cargo 分配预算在全部文本断言通过后失败，新实现通过。沿用当前线程计数器，输入构造、字典/逆表预热、输出断言及回收在窗口外，计数仅包住转换调用。20 个输入/方向组合中，空串两组为零申请，兼容字逆转换为两次，其余 17 组均为一次；所选输出不扩容，不约束任意字形扩张必需的额外申请。新增 `⿰發發` 验证简转繁保留完整 IDS，而逆表仍输出 `⿰发发`；`PN结 SQL注入攻击` 保留 ASCII 开头词组转换。

既有真实 C ABI 离线释义分配预算仍独立排除转换成本并通过，4,096 行合成未命中请求由 12,323 次、837,928 累计请求字节变为 8,227 次、772,392 字节，空释义回复不变；本片减少 4,096 次和 65,536 字节。字节是累计请求量，不是 RSS 或设备峰值。

新增扫描单测覆盖等值多字匹配后的迟到首次变化、多次扩张/缩短、二至四字节 UTF-8 边界以及完整/不完整 IDS。内部 `Cow` 的借用/接管遵循 Rust 官方 [Cow 文档](https://doc.rust-lang.org/std/borrow/enum.Cow.html)，公开结果继续拥有内存，生命周期不逃逸本次调用。

机械包含旧新转换模块，以同一份 vendored 词表逐行对键、首值和键加合成混排/繁体 IDS 后缀执行两方向，共 328,848 次输出比较全部相等。CPU 测量覆盖空串、短长 ASCII/词组/繁体/混排、兼容字/密集兼容字、两类 IDS、ASCII 开头词组、迟到规范化/迟到转换，共 16×2 组。初始两轮九次配对的墙钟测量出现大幅长段波动，不能区分调度负载与算法成本，因此不采用它们来宣称 CPU 收益或无回退。

随后在临时模块中把两套 HashMap 的构建器统一为 `BuildHasherDefault<DefaultHasher>`，保持所有转换源码与数据相同，控制随机散列布局；生产 HashMap 保持随机种子。以本机 SDK `_time.h` 定义的 `clock_gettime_nsec_np(CLOCK_THREAD_CPUTIME_ID=16)` 测线程 CPU 时间，排除本线程被调度出去的时间。15 轮交替旧新顺序，每轮 `clamp(262_144 / max(字符数, 1), 128, 16384)` 次；字典预热、输入构造和对照不计时，转换与输出回收计时。受控模块再次完成 328,848 次相等对照。各轮平均单次耗时中位数：长 ASCII s2t 为 811,004→807,715 ns（配对旧/新中位比 1.006），t2s-char 为 85,103→79,612 ns（1.061）；密集兼容字 s2t 为 155,120→155,612 ns（0.997），迟到转换 s2t 为 796,135→790,279 ns（1.008）。30 组非空配对比 0.997–1.148，空串分别 1.361/0.999，不放大纳秒级空串差异。

受控 CPU 测量未复现初始墙钟的大幅回退，但控制散列种子改变了桶布局，CPU 频率/缓存和宿主负载仍会影响结果；结论是确定减少无变化缓冲，CPU 多数持平或小幅改善，不宣称所有文本或生产端到端延迟均加速，不设置机器间计时门禁。

`cargo test -p msime-client-core -p msime-host-api --locked` 全部通过：client-core 1,423 项单元测试、6 项集成测试，Host API 624 项单元测试、14 项集成测试，两包文档测试通过，共 4 项原有忽略用例。

`cargo clippy -p msime-client-core -p msime-host-api --locked --all-targets -- -D warnings`、Rustfmt、差异空白检查与笔记门禁通过。独立复核没有阻塞或重要问题，并重跑八项核心转换测试与真实函数分配回归；对受控 CPU 方法和结论边界复核通过。

`CARGO_BUILD_JOBS=6 bash scripts/verify-local.sh --quick` 退出 0：契约、笔记、Rust workspace、Android target、Wasm、Android 宿主 JVM、原生 macOS 与共享 Apple bridge 检查通过。首次 workspace 检查因宿主 bundle 尚未构建跳过 `msime-desktop`，后续 Android target 和原生 macOS 构建完成；Linux 缺 Docker，Windows/pipe-only 缺 MinGW 或 Windows 宿主，Harmony 缺工具链/预备资源而跳过。本片无文件系统、权限或 Android 资源变化；这些编译/JVM 检查不是设备验收。

## Consequences

未变化的阶段借用原文，避免重复全量复制；最终拥有型字符串、实际转换缓冲及其必要扩容和首次字典/逆表初始化仍有成本。第一次差异前需比较匹配片段，物化后每段仍检查输出是否已存在，密集变化保留这点分支代价。两轮扫描共用原最长匹配和 IDS 规则，逆表继续逐字符处理，不能因复用物化流程而改变 IDS 内的转换行为。后续[首字节过滤](2026-10-14-chinese-prefix-byte-filter.md)独立排除必然失败的前缀查询，借用/物化决定不变。没有增加会话缓存、公共接口或依赖，也未改变文件读写、权限或 Android 资源。
