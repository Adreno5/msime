# Agent Note: 插件文本逐行借用迭代

Status: implemented

## Problem

单词本和辅助码共用的 `data_lines` 先收集整个文件的行号与切片，再交给顺序消费的解析循环。空行和注释也进入数组；512 KiB 的纯换行文本会在消费首行前申请一个 24 MiB 数组。

## Decision

`data_lines` 返回借用输入缓冲的迭代器，按需产生从 1 开始的行号和行切片。函数仍在返回迭代器前剥离开头 BOM 并校验整个文件的 UTF-8，使用 `split('\n')` 保留空文件与尾空行，只去掉每行一个末尾 `\r`。调用方继续顺序消费，不保存额外的全文行索引。

这与[单词本空解析延后条目缓冲](../testing/2026-10-11-wordbook-lazy-entry-buffer.md)部分重叠：该决定约束解析结果容器的预留时机，本决定去掉共用行拆分的临时容器，二者各自保留。

检索 `data_lines`、插件解析、单词本、`wordbook` 与 `helpcode` 后，没有其他持有行拆分契约的活跃笔记；HarmonyOS 共享沙箱提案讨论插件文件所在目录，与内存解析无关。

## Verification

三项行为测试在旧实现上通过，覆盖 BOM、CRLF、行号、空文件、尾空行和后段无效 UTF-8；改动后插件模块 88 项测试通过。直接提取源码函数，用合成输入与分配计数器测量构造结果至取得首行的额外堆分配，排除输入创建：20,000 行记录、512 KiB 换行和 512 KiB 注释分别从 14、19、17 次分配降为零。零分配预算在原实现失败、迭代器实现通过。

## Alternatives considered

- 保留全文数组：调用方可以索引或重复遍历，但现有两个调用方都只顺序遍历，数组会为全部空行与注释申请存储。
- 使用 `str::lines()`：直接表达按行遍历，但它省略空文件与尾部空行，改变现有行拆分契约。

## Consequences

行拆分不再申请全文索引数组，额外内存不随行数增长。整个文件的 UTF-8 校验仍是必要的前置扫描；输入缓冲、有效词条和去重集合仍占用内存，本决定不声称整个导入过程零分配。以后若调用方需要随机访问或重复遍历，需自行明确收集的范围与内存预算。
