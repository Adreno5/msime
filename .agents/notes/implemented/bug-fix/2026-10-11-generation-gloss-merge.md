# Agent Note: 同代次候选释义合并与空结果边界

Status: implemented

## Problem

在线候选更新已经保留前后同文词条的释义，但下一轮离线或部分在线结果经 `apply_translations` 整体替换后仍会丢失未回答词条的释义。Fcitx5 的任务种子只保护一个宿主，其他宿主仍会闪烁。空数组同时被宿主用于关闭翻译或切换目标语言时主动清理，不能一律当成无更新。

## Decision

共享运行时按当前候选代次合并非空结果，新结果覆盖同词旧释义，旧代次照旧拒绝；只保留当前候选范围内的释义，避免多次部分回包积累请求外条目。空数组仍主动清空，Android/iOS 宿主的异步空结果跳过应用，保留原有失效、渲染和后续在线调度；macOS 宿主恢复上游行为，不在本 PR 范围内。命令翻译的独立分支不变。同代次非空回包复用 `retain_candidate_translations` 过滤当前候选：去重后的回包条目数或候选数不超过 8 时直接比较，两侧都大时才建立借用候选文本的哈希集合。是否主动清理在过滤前判定，过滤掉全部范围外词条仍是无更新。

同代次回包只有在当前候选的释义新增或变更时才推进 `candidates_epoch`；重复同值与候选范围外的回包不改变视图，也不应让生命周期核心误报 `candidates_shown`。空数组仅在原有释义非空时推进计数器。

Fcitx5 移除当前页任务种子；翻译任务只合并本轮离线与在线结果。在线候选刷新前后分别执行释义保留判断；[交集保留](2026-10-11-online-candidate-gloss-retention.md) 在空表或小侧不超过 8 条时跳过临时哈希集合，两侧都大时继续用 `HashSet<&str>`，引用不跨越刷新。

合入 `23ba3a6d7` 后，AI 空回答把占位行从 `…` 改为 `—` 也走同一交集保留刷新；它不改变输入，不能顺便清掉本地候选释义。仍推进代次并拒绝旧结果，随后真实输入变化仍清理。

## Alternatives considered

- 每次回包都建立完整候选集合，比较复杂度稳定、实现直观；但 1 至 8 条释义也支付完整列表的扫描与临时存储。复用交集保留函数的小侧阈值，避免维护第二份过滤规则。
- 先按候选过滤再判断空回包，可以合并控制流；但非空的范围外回包会因此清掉已显示释义，违反同代次合并边界。

- 继续用 Fcitx5 的当前页种子，改动局限于一个宿主；但同根因在 IBus、Windows 和移动宿主仍存在，逐宿主复制展示状态会继续漂移。
- 新增显式清理 ABI，让空结果统一是无更新，所有调用方更容易表达意图；但要扩展各平台桥接层，现有空数组清理调用也需迁移。本次保留接口，用结果边界区分主动清理与异步无答案。
- 所有回包直接扩展释义表，最少代码且空回包自然无更新；但会破坏现有主动清理语义，并让多次回包积累候选之外的条目。

## Verification

### 稀疏回包过滤

检索 `apply_translations`、`retain_candidate_translations` 和稀疏释义：本篇持有回包合并与空数组边界，[交集保留](2026-10-11-online-candidate-gloss-retention.md)持有已显示释义在在线刷新前后的交集规则，复用其过滤函数，不另起笔记。标准库 [`HashMap::retain`](https://doc.rust-lang.org/std/collections/struct.HashMap.html#method.retain) 的容量扫描成本已核对。

分配回归以合成 Runtime 调用真实 `apply_translations`，与相同输入的去重 `HashMap` 对照；输入字符串在计数之外建立，当前同值释义已预置以排除新增存储。32、1,024、4,096 行乘以 1/7/8 条释义的九组旧代码多一次申请，分别额外申请 1,096、34,824、139,272 字节，零额外存储预算真实失败。另有 0/1/8 行乘以 9/32 条回包的六组小列表预算；旧代码在非空小列表失败。申请字节是 64 位宿主的累计分配器请求，不代表 RSS、快照、视图或设备延迟。

语义回归跨 0/1/8/9/32/1,024 行与 1/8/9/32 条回包，覆盖最后重复值胜出、未回答释义保留、同值重放不推进 epoch、范围外非空回包不清理、显式空回包仅在需要时推进 epoch；旧代码均通过。旧代次回包在消费输入迭代器之前被拒绝，且不分配。

最终十五组预算均不超过相同输入去重表的分配次数与申请字节，九组稀疏大列表的额外申请均为零。完整 Runtime 268 项及文档测试、全部 target 的 Clippy（警告视为错误）通过，Rustfmt 与笔记校验通过。独立只读审查未发现阻断或重要问题，阈值措辞已澄清；审查另外执行了四项新增与四项既有相关测试。

固定基线 `947a486c2ec2a4157d5e1a522b88aed1af85b903` 与当前 `apply_translations`、保留函数机械提取到最小合成 Runtime，以 `rustc -O` 在同一程序做九轮交替配对；命令查询固定为 `None`，候选和已有同值释义预先建立，输入字符串及批次克隆不计时。计时包括回包去重、过滤、同值合并检查及输入回收，排除引擎、快照、真实命令查询、视图、插件和设备。七种长度（0/1/8/9/32/1,024/4,096）×四种释义数（1/8/9/32）×两种等长文本公共前缀（4/256 字节）共 56 组，命中在列表末尾；每轮迭代 `clamp(262_144 / max(行数, 32), 256, 2_048)` 次（整数除法）。4,096 行、4 字节前缀的各轮平均单次耗时中位数：1 条 107,660→8,279 ns，8 条 108,744→64,991 ns；256 字节前缀的 8 条 333,725→244,650 ns。两侧都超过 8 的 9/32 条回包保持哈希分支，配对旧/新比中位数约 0.978–1.071，额外遍历和噪声仍存在；空候选、1 条、4 字节前缀约 69→75 ns。结果支持该合成输入的过滤成本改善，不代表端到端延迟，不设机器间计时门禁。

本轮 `CARGO_BUILD_JOBS=6 bash scripts/verify-local.sh --quick` 通过：契约检查、149 项本机 Windows 策略测试、Rust 工作区、Android target、Wasm、Android 宿主 Java 冒烟、macOS 原生宿主和共享 Apple 桥接编译。Linux 缺 Docker、Windows 缺 MinGW、HarmonyOS 缺工具链与预置资源，相应构建跳过；未做设备输入法验收。

### 既有合并验证

同代次部分回包与请求外词条的两条 Rust 回归先失败，修复后 Runtime 177 项、Host API 428 项通过。Fcitx5 原生云/AI 与 `ibus-empty-translation` 均先在异步空结果清掉译文的断言失败，修复后通过；主动关闭翻译仍能清理。IBus 完整冒烟在先行语音用例失败，翻译回归单独登记，未掩盖无关失败。

后续回归覆盖同值回包与候选范围外回包的 `candidates_epoch` 不变：断言先在重复同值处失败，修复后通过。生命周期核心以该计数器决定是否产生 `candidates_shown`，故此处在运行时阻止虚假的视图事件。

macOS 宿主连同其卡片用例整体恢复上游，本 PR 不再改动、也不声称验证 macOS；Linux 无 Apple 宿主与 Android JVM 工具链，两条源码接线契约验证 Android 与 iOS 的空结果守卫、离线记账和服务调度顺序，不替代原生运行验收。Windows、HarmonyOS 已有空结果守卫，不改其路径。

源码接线检查沿用仓库已有 `scripts/test-*.py` 契约入口，只钉住 Android 与 iOS 的空结果守卫、异步记账/调度及显式清理路径，不是替代平台测试的策略。优先用原生测试，但缺相应宿主时不能执行；不为了这次修复搭建新跨平台模拟层。合入上游后，AI 空座位保留释义回归先失败，复用交集刷新后通过，输入改变仍清理、旧代次仍拒绝。

## Consequences

稀疏回包和小候选列表不再申请全候选集合，去重用的输入 `HashMap` 和新增释义的常驻存储仍可能分配。两侧都大继续使用哈希过滤；复用保留函数会先遍历回包表再消费它，仍存在表容量扫描成本，不改变词条身份、代次、命令翻译、公开接口或宿主调度。

共享合并覆盖所有宿主，现有主动清理无需迁移 ABI。代价是本 PR 的宿主必须在异步空结果处跳过应用，仍保留渲染和后续在线调度；macOS 宿主恢复上游后，其异步空结果边界本 PR 不保证修复，也未经 CI 验证。源码接线契约依赖现有控制流形状，重构时需与原生测试同步，Linux 与共享测试不等于其他平台真机验收。
