# Agent Note: 社区列表按请求代次接收结果

Status: implemented

## Problem

社区页允许在前一次加载尚未完成时重新请求同一个搜索词和分类。旧回调只比较筛选参数；两次参数相同时，旧结果仍会填入新列表，随后新结果再次追加同一批卡片。

## Decision

每次实际发起列表请求时增加代次。回调先核对代次，再核对现有筛选条件；过期请求不改变 `loading`、列表或错误状态。视图重建会重新发起请求，自然获得新代次。

## Alternatives considered

只禁止加载期间再次请求可以避免重叠，但会让用户的主动重试和新的搜索必须等待旧请求完成，也与当前切换分段时立即刷新列表的行为冲突。

## Consequences

同参数连续请求时，旧回调不能填充新列表或清掉新请求的加载状态。分页请求也会得到代次；它们原本依靠 `loading` 顺序执行，代次检查不改变正常分页顺序。回归契约先在旧实现上失败，再在修复后通过；Android 宿主编译和 smoke 测试通过。
