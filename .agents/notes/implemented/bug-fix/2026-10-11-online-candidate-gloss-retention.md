# Agent Note: 在线候选更新保留未变化词条的释义

Status: implemented

## Problem

Fcitx5 的重复请求已去重，但真实云或 AI 候选首次到达仍会推进候选代次，`Runtime::refresh()` 清空整份译文，未变化的词条也随之短闪。单独保留这一刻的译文还不够：后续离线探测没有命中、在线回包只回答新词条时，翻译任务仍可能用不完整结果覆盖原页。

在线刷新原先还无条件为前后完整列表创建两份文本哈希集合，未显示释义时也会申请同样的临时存储；稀疏释义的保留成本由完整候选列表决定。

## Decision

共享运行时在成功应用或移除在线候选时，只保留刷新前后都存在的候选文本对应的已显示释义。输入变化、取消、换方案、快照失败仍清空释义；新词条不继承旧释义，候选代次继续推进，旧候选 ID 和迟到翻译仍被拒绝。不改 C ABI 或引擎排序。保留判断在释义表为空时立即跳过；释义表或候选列表不超过 8 条时直接线性匹配，比较次数受小侧上限约束；两侧都大时使用借用候选文本的哈希集合。前后各自判定，借用不跨越刷新。

当前页任务种子的宿主方案由[同代次释义合并](2026-10-11-generation-gloss-merge.md) 部分取代：共享层合并非空结果，宿主异步空结果跳过应用，空数组主动清理的既有接口保留。候选交集与代次决定继续成立，不维护另一份缓存或跨输入历史。

## Alternatives considered

- 宿主缓存译文再按新代次回填，能只影响 Fcitx5；但会复制共享展示状态，并绕过核心代次校验，同根因在其他宿主仍存在。初版只从有效视图取任务种子，没有恢复旧快照；该局部补齐仍不能保护其他宿主，现由共享合并取代。
- 所有刷新都保留同名词条，代码更短；但相同文字可能属于新组合，不能据此认定旧上下文仍有效。
- 等新译文全部完成才显示新候选，能让新行也一步显示；但网络慢或失败时会拖住真正的新候选。

- 始终为完整候选列表建哈希集合，复杂度稳定，但没有释义时仍遍历所有文本并分配，少量释义也支付整张列表的临时存储。
- 所有数量都用线性查找，完全取消临时集合，但两侧都大时退化为平方比较；本方案只在小侧不超过 8 条时使用它。

## Verification

共享 Rust 回归使用真实 Engine 会话，覆盖云与 AI、单条与批量、借用与所有权转移八种组合，以及前后候选交集、删除词条、未请求词条、旧代次回包、旧候选 ID、输入改变和快照失败。保留判断之前真实失败，修复后 `cargo test -p msime-input-runtime --locked` 的 174 项及 Host API 的 428 项测试通过，Rust 格式与 clippy 校验通过，最终 Linux 全量 `ctest` 83 项、quick 门禁及笔记校验均通过。

原生 Fcitx5 回归先通过真实翻译 socket 显示本地译文，再注入首次在线回包；云、AI 两条路径均在旧代码的「新在线候选到达使未变化候选的译文消失」断言失败。另移开合成释义缓存并模拟离线资源缺失，离线转在线且回包为空时，两条路径在补任务种子之前均失败，补齐后通过。运行命令为 `ctest --test-dir target/linux-ibus -R '^fcitx5-native-(context|ai)$' --output-on-failure`。

隔离真实 daemon/frontend 覆盖云、AI、云回包延迟 400ms、AI 回包延迟 2s，以及两种延迟下在线仅回答新词条的部分回包，共六个场景。观察已显示的 `你好` 释义在新候选到达和后续翻译回包时持续存在；仍覆盖清缓存、新组合与 AI 空缓存的网络回退。已安装旧库的延迟场景作为对照真实失败，新构建通过；全部输入、服务响应和状态都是合成夹具。

分配测试比较同一合成快照的普通 `refresh` 与 `refresh_online_candidates`，排除共同的引擎快照分配，并保留真实排序、插件旁路和刷新流程。0、1、8 条释义在 32、1,024、4,096 行旧实现上均多 2 次分配，额外申请字节为 2,192、69,648、278,544，零额外分配预算真实失败；优化后这九种组合均为 0 次额外分配与 0 字节额外申请。申请字节包含分配器请求，不代表 RSS 或峰值驻留内存。原有测试计数器移到共享测试模块，复用到插件与释义回归，生产库不带计数器。

辅助函数计时提取当前源码，用 `rustc -O` 与原保留实现交替测量 240 轮，克隆释义表在计时之外，每轮比较完整结果。4,096 行、4 字节公共前缀、释义命中列表末尾时，1 条中位数为 112,375→8,292 ns，8 条为 111,667→65,917 ns；256 字节公共前缀的 8 条为 335,583→241,833 ns。9 条及 32 条沿用哈希分支，计时接近原实现。测试覆盖 32、1,024、4,096 行和 0/1/8/9/32 条，结果只支持该合成输入下的保留判断，不代表端到端延迟，也不设机器间计时门禁。

完整运行时 256 项与文档测试、Clippy、Rustfmt、笔记校验和本地 quick 门禁通过；独立只读审查未发现阻断问题。quick 包含 Rust 工作区、Android target、Wasm、Android 宿主 Java 冒烟、macOS 原生宿主及共享 Apple 桥接编译；Linux 缺 Docker、Windows 缺 MinGW、HarmonyOS 缺工具链和预置资源而跳过，本轮不声称设备输入法验收。语义回归覆盖稀疏/哈希阈值、重复词、新增词不得继承旧列表外释义、删除词，以及大释义表收缩到 0/1/8/9 行。旧有真实 Engine 回归继续覆盖云/AI 的八种入口、代次、输入改变和快照失败。

## Consequences

在线候选可以立即显示，未变化的词条不再先丢释义再补回；已移除与从未显示的词不会借用旧释义。新词条仍等待有效翻译结果，不伪造释义，也不延迟新候选。无释义时不遍历候选；稀疏保留不申请全候选哈希存储，仍有有界线性比较与释义表内部容量扫描成本。共享展示行为影响所有 Host API 宿主，本机验证不能替代其他平台真机验收。
