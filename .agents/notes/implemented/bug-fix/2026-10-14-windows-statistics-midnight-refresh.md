# Agent Note: Windows 原生统计页跨午夜刷新

Status: implemented

## Problem

Windows 原生统计页的定时读取只在统计文件内容变化时重画。午夜后如果没有新输入，文件签名保持不变，页面仍用昨天的本地日期计算「今日」指标、趋势窗口和按日明细。

## Decision

把本地日期作为统计页刷新状态的一部分。每次可见轮询和窗口重新激活都比较当前日期；日期推进时，即使统计文件签名不变，也重画页面。统计内容仍只在签名变化时替换，避免无意义地复制和重建整页数据。

## Alternatives considered

每次轮询都无条件重画可以覆盖日期变化，但会破坏现有的重复数据抑制。另设午夜定时器会增加窗口生命周期和系统时钟变化的处理分支；复用已有的 5 秒轮询和激活入口更简单。

## Verification

为日期变化判定补充模型测试；`typing-statistics-model` 测试通过，`pnpm run verify-notes` 和 `bash scripts/verify-local.sh --quick` 通过。Windows 原生 UI 无法在当前 macOS 环境启动，因此用纯模型测试和代码路径检查验证日期失效逻辑；quick 门禁报告 Windows 原生测试中 149 项通过、64 项需要 Windows 构建。

## Risks

日期变化会额外重建一次设置页；它只发生在本地日切换时，且不触发统计文件读写之外的新工作。后台窗口不运行轮询时，页面会在重新激活时更新。

## Consequences

统计页在可见状态下最迟下一次轮询推进到新日期；后台窗口在重新激活时推进。统计文件没有变化时仍不会替换统计快照。
